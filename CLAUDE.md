# DZ_mesh — контекст проекта для Claude

Этот файл — передача дел из другого чата. Прочитай целиком перед любой правкой.
Положи его в корень репозитория как `CLAUDE.md` и закоммить: Claude Code читает
его автоматически в каждой новой сессии.

## Кто пользователь и как с ним работать

- Иван, учитель. Не программист, но
  уверенно тестирует и присылает скриншоты. Общаемся по-русски, просто, без жаргона.
- Школьный ноутбук Windows, **Яндекс Браузер**, расширение загружено как
  «распакованное» через `chrome://extensions`.
- Проверить код на настоящем МЭШ мы не можем — только Иван. Поэтому:
  всё проверяем на **макете страницы** (см. `test/`), честно говорим, что на
  живом МЭШ не проверено, и просим скриншоты, если чего-то не знаем об интерфейсе.
- Сначала Иван обычно просит визуал, потом логику. Если он говорит
  «логику пока не трогаем» — не трогаем.

## Что делает расширение

Chrome-расширение (Manifest V3) для МЭШ (school.mos.ru, кабинет учителя):
для уроков выбранного дня проставляет домашнее задание с текстом **«Не задано.»**,
если на уроке ДЗ не выдано. Всё делается кликами по интерфейсу, как человек.
**Никаких токенов, паролей, прямых запросов к API** — это принципиальное решение.

Репозиторий: `ivangusarov386-lab/DZ_mesh`, рабочая ветка
`claude/repo-unpack-build-ea38zy` (в `main` только исходная загрузка архива).

| Файл | Роль |
|---|---|
| `manifest.json` | MV3; `inject.js` в MAIN world, `content.js` в isolated world, оба на `https://school.mos.ru/*` |
| `inject.js` | Подменяет `window.fetch` только для чтения: пересылает ответы расписания через `postMessage` |
| `content.js` | Пересылает данные в расширение; по команде открывает урок и создаёт ДЗ кликами |
| `background.js` | Service worker: очередь уроков, лог, ретрай, стоп. Попап может закрываться — работа идёт здесь |
| `autopilot.js` | Автопилот по расписанию (в разработке, см. «Идеи на будущее»); подключается в `background.js` через `importScripts` |
| `popup.html/js` | Кнопка «Загрузить неделю», дни, список уроков с галочками, запуск/стоп, лог, блок автопилота |
| `icons/notify-128.png` | Иконка для `chrome.notifications` (нужна автопилоту) |

## Факты про МЭШ (выяснены на практике, важны!)

**Эндпоинты расписания** (перехватывает `inject.js`):
- `/api/ej/plan/teacher/v1/schedule_items?...from=` — обычные уроки (у них в
  подсказке кнопки «К журналу» + «К уроку»). **Только они идут в очередь.**
  Поля: `id`, `date: [Y,M,D]`, `time: [h,m]`, `group_name`, `group_id`, `class_unit_id`.
- `/api/ej/ec/teacher/v1/ec_schedule_items` — внеурочка (бейдж «ВН»), пропускаем, только считаем.
- `/api/additional_education/v1/ae_schedule_items` — доп. образование («доп»), пропускаем, только считаем.
- `/api/ej/core/teacher/v1/homework_presence` — **зелёный «домик»**. Он означает, что на
  этот урок надо СДАТЬ ранее выданное ДЗ, а НЕ что ДЗ выдано на уроке.
  **Не использовать для решения «есть ДЗ / нет ДЗ»** — это была ошибка.

**URL**: расписание `/teacher/account/schedule`, урок `...schedule?scheduleItemId=<id>`,
журнал класса `/teacher/study-process/journal/my/<group_id>` (сам `<group_id>` — тот же,
что в `schedule_items[].group_id`, предположение, не проверено; номер урока в адресе
журнала (`?scheduleItemId=`) проверен и совпадает).

**Журнал класса — второй источник статуса ДЗ, СО СВОЕЙ ВЕРСИЕЙ ТОЙ ЖЕ ОШИБКИ,
что и «зелёный домик» в расписании** (найдено 28.09.2026, скриншот DevTools от
Ивана; ошибка обнаружена на живом МЭШ 29.09.2026). В коде страницы журнала у
каждой клетки урока есть атрибут `data-test-component="scheduleLessonCell-<id>-<СТАТУС>"`,
например `scheduleLessonCell-625305037-HOMEWORK` и `scheduleLessonCell-625305113-DEFAULT`.
**`<id>` — тот же номер, что и `scheduleItemId` урока** — проверено Иваном напрямую
(клик по дате в журнале дал ссылку с тем же числом), это верно и полезно само по
себе. **А вот сам статус `HOMEWORK` на клетке урока — НЕ значит «ДЗ задано именно
на этом уроке»** — 29.09 статус `HOMEWORK` встретился на уроке, где Иван вживую
видел красный домик (ДЗ не задано). Судя по всему, `HOMEWORK` на клетке означает
«на эту дату нужно СДАТЬ какое-то ДЗ» (в т.ч. заданное раньше) — ровно та же
путаница, что и с `homework_presence`/зелёным домиком, просто в текстовом виде и
на другой странице. **Чтобы узнать, задано ли ДЗ ИМЕННО на уроке, нужно смотреть
статус СЛЕДУЮЩЕЙ после него клетки** (туда должен попасть срок сдачи, если
задание только что создано) — так же, как на странице урока смотрим «Проверить
к» строго позже даты урока (правило v5.1). См. «Текущее состояние кода» —
`peekJournals()` в `background.js` сейчас только логирует статус следующей
клетки для сравнения, ничего не пропускает. Не проверено: других статусов кроме
`HOMEWORK`/`DEFAULT` не видели. Читается через `readJournalCells()` в
`content.js` — сканирует DOM (`querySelectorAll`), а не перехватывает fetch, в
отличие от `inject.js` (не нашли, какой запрос наполняет эту таблицу); порядок
элементов в массиве — порядок документа слева направо, то есть хронологический.

**Панель «Домашнее задание» на странице урока:**
- Пустая: текст «Домашнее задание отсутствует» + кнопки «Без домашнего задания»
  и «+ Создать домашнее задание».
- Кнопки **«Без домашнего задания» и «Создать домашнее задание» лежат в одном
  контейнере** и есть **всегда** — и когда ДЗ нет, и когда есть. Клик по первому
  элементу, «содержащему текст», попадал в контейнер и ничего не делал
  (главная причина старой ошибки `no-textarea`). Кликать только **самый глубокий**
  видимый, активный, не перекрытый элемент (`findClickable` в `content.js`).
- Карточка задания: «Задание 1», текст, «Когда задано: 21.09.2026 в 21:39»,
  «Проверить к: 28.09.2026», «Для учеников: 29 из 29». Надписи «Задание №1» нет.
- **На странице урока показываются ТОЛЬКО задания, которые надо СДАТЬ на этом
  уроке** (выданы раньше) — **задание, выданное ИМЕННО на этом уроке, в этой
  панели не появляется ВООБЩЕ** (найдено 04.10.2026 на живом МЭШ вместе с
  Иваном, другой сессией через Claude in Chrome — см. «ГЛАВНАЯ ОШИБКА: дубли»
  ниже). Оно видно только в правой колонке СЛЕДУЮЩЕГО урока этого класса, в
  разделе «дом. задание». **Старое правило v5.1 («выдано, если есть карточка
  с «Проверить к» строго позже даты урока») было НЕВЕРНЫМ** — оно иногда
  случайно совпадало с правильным ответом, потому что та же правая колонка
  тоже попадает в `document.body.innerText`, который парсит `dueDates()`, но
  колонка загружается ПОЗЖЕ основной панели, и из-за этого три раза подряд
  создавало дубль «Не задано.» одному и тому же уроку. Правильное правило и
  фикс — см. «ГЛАВНАЯ ОШИБКА: дубли» в «Текущее состояние кода».
- МЭШ сам ставит дату проверки (обычно следующее занятие; раньше «сегодня+2» нельзя).
- **Страница урока грузится медленно — спиннер крутится до ~20 секунд**
  (замечено 04.10.2026 на живом МЭШ). Все ожидания «панель дорисовалась»
  должны быть не меньше 30 секунд (раньше местами стояло 12 — не хватало).

**Экраны после «Создать домашнее задание»** — порядок бывает разный, поэтому
в `content.js` цикл «смотрю на экран → жму подходящее → жду, что экран изменился»:
1. окно «Добавить материалы из урока КТП?» → «Прикрепить»;
2. каталог «Прикрепление материалов к домашнему заданию» → «Открыть описание»
   (или «Прикрепить», если что-то выбрано; неактивная кнопка — не считается кликом);
3. форма: `textarea[placeholder="Введите значение..."]` → вписать текст;
4. «Выдать задание» → окно подтверждения «Выдать домашнее задание» (бывает не всегда).
Успех: появилась новая карточка с «Проверить к» позже даты урока, и форма
и окно подтверждения закрыты (в самой форме тоже видна дата «Проверить к»!).

**«Начать урок» = запустить сценарий урока** (найдено и проверено руками на
живом МЭШ 04.10.2026, другой сессией вместе с Иваном через Claude in Chrome —
подробности см. в истории чата, если понадобятся; здесь — только выжимка
фактов). Отдельной кнопки смены статуса урока в МЭШ действительно нет (это
было решено ещё 30.09.2026, см. «Идеи на будущее»). В блоке «Материалы к
уроку» у материала с подписью **«Сценарий урока»** та же самая кнопка «...»,
что и у обычных материалов (`data-test-component="materialCardMenuList-<uuid>"`
— подтверждено дважды: и для видео, и для сценария), но в открывшемся меню
«Действия с материалом» нужен пункт **«Запустить»** (обычная ссылка
`target="_blank"` с параметром `activity_url`), а не «Просмотреть». Открывает
**новую вкладку** `https://uchebnik.mos.ru/composer3/lesson/<id>/management`,
заголовок «Урок: <название сценария>»; страница урока в МЭШ после этого не
меняется. На странице сценария сверху есть таймер — как он выглядит и что
показывает в конце, не видели (нужен скриншот). «Завершить урок» = закрыть
эту вкладку и вернуться в МЭШ. У урока может быть несколько сценариев (видели
два) — какой запускать в этом случае, не решено, пока берём первый. Материал
нужного типа называется именно «Сценарий урока» — бывают и другие типы
(например, «Видеоурок»), их не трогаем.

## Текущее состояние кода

- `content.js`: цикл по экранам, пошаговый лог (`hw-step` → строки «· нажимаю …»
  в попапе), диагностика при сбое (кнопки на экране, текст окна).
  **Человеческий режим** вверху файла: `HUMAN_MODE = true`, `SPEED = 1` —
  нарисованный курсор ездит к кнопкам, паузы, печать по буквам, пауза между
  уроками 1,5–3 с. Ивану курсор понравился — не убирать без спроса.
- Все уроки дня открываются и проверяются по странице урока (не по домикам).
- **v5.1 (due-date правило) применён** (коммит `0edb502`, через `git am`,
  авторство сохранено как есть — патч написан другой сессией). `node --check`
  пройден, прогнан на макете (`test/run_mock.js`) — сценарий «только ДЗ к
  сдаче (28.09) → создать» даёт `на уроке только ДЗ к сдаче (проверить к
  28.09.2026) — выданного на этом уроке нет, создаю`, сценарий «уже выдано
  (к 30.09) → пропустить» даёт `ДЗ на этом уроке уже выдано (проверить к
  30.09.2026)` — оба совпадают с ожиданием. **На живом МЭШ похоже, что
  работает правильно** (Иван, 29.09.2026, после переустановки расширения —
  см. ниже про сбой обновления): «вроде всё работает правильно», но сам
  уточнил, что это не окончательный вывод — «буду ещё проверять/смотреть».
  Так что считать полностью подтверждённым на живом МЭШ пока рано, но
  первый реальный прогон прошёл без замечаний.
- **Попап реконсилирован**: взят `popup.js` из `reference/popup_v5_other_chat/`
  целиком (собственная реализация в ветке не сортировала дни как число —
  баг «октябрь перед сентябрём» — и не переименовывала кнопку в «Продолжить»).
  `background.js`/`popup.html` в ветке уже совпадали с `reference/` побайтово,
  правки не потребовалось. Проверено интерактивно (headless Chrome, синтетические
  `schedule_items`): порядок дней 28.09 перед 01.10, чекбоксы по умолчанию все
  отмечены, «Снять все»/«Выбрать все» переключают разом, кнопка на новый день —
  «Проверить и поставить «Не задано.» (N урок(ов))». Живой МЭШ не проверен.
- **Журнал пробовали подключить к принятию решений, откатили после первой же
  живой проверки (29.09.2026) — статус клетки САМОГО урока оказался не про
  то, что мы думали.** Хронология:
  1. Сначала `preCheckJournals()` в `background.js` пропускал урок целиком
     (без открытия), если статус его клетки — `HOMEWORK`. Иван попросил
     это «сам без моего участия».
  2. Первый же реальный запуск: урок обработан как «уже было», но Иван
     вживую видел на журнале, что домашнего задания там ещё нет (у него
     на скриншоте фигурировала соседняя дата с красным домиком).
  3. Разобрались: статус клетки урока — как когда-то зелёный домик в
     расписании (см. выше) — про то, что **на эту дату нужно СДАТЬ**
     что-то (в т.ч. заданное раньше), а не «задано ИМЕННО на этом уроке».
     Иван это сформулировал: «нужно чтобы смотрел на следующую дату после
     сегодня».
  4. Функция переименована в `peekJournals()`: **решений больше не
     принимает**, только пишет в лог для сравнения. Смотрит статус не
     клетки самого урока, а **следующей после неё** клетки в массиве,
     который возвращает `readJournalCells()` (тот идёт в порядке документа
     слева направо — уже хронологически, поэтому следующий элемент массива
     и есть следующая дата; парсить месяцы/заголовки таблицы не нужно).
     Это тот же принцип, что и в правиле v5.1 на странице урока («Проверить
     к» строго позже даты урока) — просто применённый к журналу.
  5. **Каждый урок снова открывается и проверяется по своей странице без
     исключений** — ни один статус журнала (включая `HOMEWORK`) сейчас не
     может привести к пропуску урока. Это временно, пока не накопится
     несколько реальных сравнений «что сказал журнал (следующая дата) /
     что реально было на странице» и они не совпадут.
  Проверено: `test/mock_journal.html`+`run_mock_journal.js` (чтение клеток,
  6/6 верно), `test/run_mock.js` (старые 6 сценариев без регрессий),
  `test/run_background_unit.js` (10/10) — подтверждает, что теперь ВСЕ
  уроки открываются независимо от статуса журнала, для урока с известной
  следующей клеткой в лог попадает её статус (`DEFAULT`/`HOMEWORK`), для
  последнего урока в своём журнале — отдельное сообщение «следующая дата
  пока не видна» (не ошибка), для сбоя открытия журнала — своё сообщение.
  **Первый живой прогон после этого фикса чуть не обманул сам себя**: Иван
  распаковал присланный zip и нажал «Обновить» в chrome://extensions, но
  лог всё равно показывал старый текст («в журнале уже видно ДЗ... — не
  открываю их») — то есть расширение продолжало работать на СТАРОМ коде,
  файлы физически не заменились (либо распаковано не в ту папку, либо
  «Обновить» не подхватил). Чинится надёжно только полным циклом: «Удалить»
  расширение в chrome://extensions → «Загрузить распакованное расширение»
  заново, выбрав папку с новыми файлами. Признак, что обновление реально
  подхватилось: в логе после «Смотрю журнал «...»...» должно быть
  «(только для сравнения)», а не «не открываю их».
  После переустановки (29.09.2026) Иван: «вроде все работает правильно» —
  но сам уточнил, что это не финал: «буду ещё проверять/смотреть». Не
  подтверждено явно, сверял ли он конкретно строки «журнал (следующая
  дата после урока): …» с тем, что было на странице урока, или просто
  увидел, что задания в целом создаются верно — при следующем обсуждении
  стоит уточнить это отдельно, прежде чем возвращать автопропуск.
- **Выключатель расширения** (30.09.2026, по просьбе Ивана — у него ещё одно
  расширение для МЭШ, подозревает конфликт между ними на одной странице).
  Чекбокс «Расширение включено» вверху попапа (`popup.html`/`popup.js`),
  состояние — в `chrome.storage.local` (`{enabled: true}` по умолчанию, добавлено
  разрешение `"storage"` в `manifest.json`). Выключено:
  - в попапе прячутся кнопки запуска, показывается жёлтая плашка-напоминание,
    `loadBtn`/`runBtn` недоступны;
  - `content.js` игнорирует ВСЕ входящие команды (`reload-schedule`,
    `open-lesson`, `check-and-create`, `open-journal`, `read-journal`) одной
    проверкой в начале обработчика — возвращает `false` и ничего не делает,
    как будто расширения на странице нет;
  - если выключили посреди запуска — попап сам шлёт `cancel-run`.
  `chrome.storage.onChanged` в `content.js` даёt эффект сразу на уже открытой
  вкладке МЭШ, без перезагрузки страницы. Настройка переживает переоткрытие
  попапа (проверено).
  **inject.js (перехват fetch) выключателем НЕ гасится** — технически не может:
  он живёт в MAIN world и не имеет доступа к `chrome.storage` (в этом и весь

`test/mock.html` — макет панели ДЗ со всеми экранами. Параметры URL:
`mode=ktp|catalog|direct|dead|weird`, `due=ДД.ММ.ГГГГ` (готовая карточка в

макет через Playwright со стабом `chrome.runtime` и печатает шаги. Запуск:
скопировать `content.js` рядом как `new_content.js` (для скорости поставить
в копии `HUMAN_MODE = false`), `node run_mock.js`. Не коммитить
`new_content.js`. 8 сценариев: пусто → создаёт; КТП-каталог → создаёт;
`nextcol=empty` → «в разделе... не значится — создаю»; `nextcol=assigned` →
«уже выдано» (мгновенно); `nextcol=slow` → тоже «уже выдано», но только
после ~2с ожидания (не решает раньше времени); без `nextcol` → отказ
`next-lesson-column-timeout` после настоящих 30 секунд (дубль хуже
пропуска); «кнопка не работает» → `stuck`; «незнакомое окно» → `unknown-screen`.

`test/mock_material.html` + `test/run_mock_material.js` — макет панели

нажаты, `{opened:true}`; `count=2` → `{opened:false,
reason:"multiple-materials"}`, ничего не нажато.

`test/run_mock_disabled.js` — проверяет обратное состояние выключателя: со

пуст. Запуск такой же: `new_content.js` рядом, `node run_mock_disabled.js`.
(У `run_mock.js`/`run_mock_journal.js` в стабе `chrome.storage` тоже есть,
с `enabled: true` — иначе `content.js` не сможет проверить настоящий путь,

`test/run_background_unit.js` — юнит-тест `background.js` БЕЗ браузера и без
Playwright: подставляет `chrome.tabs`/`chrome.runtime` через Node `vm`.
14 проверок: `peekJournals()`/`runLoop()` целиком — что ВСЕ уроки по-прежнему
открываются независимо от статуса журнала, что в лог попадает статус именно

урок в своём журнале»/«журнал не открылся» не путаются друг с другом; плюс
данные недели (`schedule_items`/`ec_schedule_items`/`ae_schedule_items`) —
приходят и фильтруются (элемент без `id`/`group_id`/`class_unit_id`
отбрасывается), переживают пересборку `state` при `start-run`, чистятся
`reset-results`. Запуск: `node run_background_unit.js` (копия `content.js`
не нужна — тестируется только `background.js`).

`test/run_autopilot_unit.js` — юнит-тест `autopilot.js` (этапы 1–3
автопилота, см. «Идеи на будущее») БЕЗ браузера: подставляет
`chrome.storage`/`chrome.alarms`/`chrome.notifications`/`chrome.tabs` через
Node `vm`. 36 проверок: авто-вооружение дня ставит будильник ровно на
(время первого урока − 20 минут); срабатывание будильника показывает
уведомление с двумя кнопками и числом уроков; кнопка «Да, начинаем»
подтверждает план; кнопка «Отменить на сегодня» снимает его; будильник на
план с чужой датой или опоздавший (первый урок уже начался) — уведомление
не показывается, план тихо снимается; ручной запуск (`autopilot-manual-
start`) подтверждает план сразу, без единого будильника и уведомления;
`autopilot-arm`/`autopilot-manual-start`/`autopilot-open-material`/
`autopilot-close-material` отказывают при выключенном общем переключателе
расширения (`autopilot-status` при этом всё равно отвечает); открытие
материала урока при 0/1/2 материалах (`chrome.tabs.sendMessage` в стабе
имитирует ответ content.js, `chrome.tabs.onCreated` — появление новой
вкладки); закрытие по конкретному id урока (открытой/несуществующей
вкладки) через `chrome.tabs.remove`; закрытие БЕЗ id урока (как теперь
шлёт попап после бага 30.09.2026 «Закрыть не реагирует») — закрывает все
сейчас отслеживаемые вкладки разом, и корректно отвечает `closedCount:0`,
когда открытых нет. Запуск:
`node run_autopilot_unit.js` (копия `content.js`/`background.js` не нужна).

`test/run_reload_schedule_unit.js` — юнит-тест обработчика `reload-schedule`
в `content.js` БЕЗ браузера (Node `vm`, фейковый `location` с `href`/
`reload()`). 3 проверки (баг 01.10.2026 «Загружено уроков за неделю: 0»
при нажатии со страницы одного урока): уже на чистой сетке недели →
`location.reload()`; на странице урока (`?scheduleItemId=...`, как после
`open-lesson`) → настоящая навигация на чистый адрес сетки, а НЕ reload
того же урока; на странице журнала → навигация, как и раньше. Запуск:
`node run_reload_schedule_unit.js` (копия `content.js` не нужна).

`test/run_schedule_persist_unit.js` и `test/run_material_persist_unit.js` —
проверяют устойчивость `state.weekLessons`/`ecCount`/`aeCount`
(`background.js`) и `materialTabs` (`autopilot.js`) к перезапуску service
worker'а: грузят соответствующий файл ДВАЖДЫ в разные `vm`-контексты с
ОБЩИМ объектом вместо `chrome.storage.local` (имитация «SW выгрузили из
памяти и подняли заново») и проверяют, что вторая загрузка видит то, что
сохранила первая, сама ничего не отправляя/не открывая. По 2 проверки
каждый. Запуск: `node run_schedule_persist_unit.js` /
`node run_material_persist_unit.js` (копии других файлов не нужны).

Playwright в облачной песочнице Claude: версия по умолчанию (`npm i playwright`)
иногда ждёт ревизию Chromium, которой нет на диске (`chromium_headless_shell-XXXX`
не совпадает с предустановленным `chromium-YYYY`) — `npx playwright install`
запускать нельзя (нет сети на скачивание в этой среде). Обход: запускать
`chromium.launch({ executablePath: "/opt/pw-browsers/chromium", args: ["--no-sandbox"] })`
вместо `chromium.launch()` — но только в своей локальной копии скрипта для
проверки, сами `run_mock*.js` в репозитории не трогать (в другой среде, где
Playwright сам скачал браузер, они и так сработают).
